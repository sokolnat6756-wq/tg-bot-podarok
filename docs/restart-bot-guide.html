Как обновить настройки и перезапустить бота

Интерактивная шпаргалка для учеников: что делает commit/push, почему сервер сам не обновляется, и как правильно перезапустить бота на компьютере и на VPS.

1. Главная ловушка: commit и push ≠ обновление сервера

Commit сохраняет изменения в истории Git. Push отправляет их на GitHub / GitLab. Сервер с ботом сам ничего не скачивает. Пока вы не зайдёте на сервер и не сделаете `git pull` + пересборку, там продолжит работать старая версия.
Ваш компьютер
Правите код, меняете `.env`, тестируете `python run.py`
↓ commit + push
GitHub
Хранилище кода. Это ещё не сервер бота.
↓ git pull + docker compose up --build
VPS / сервер
Только здесь бот реально отвечает пользователям 24/7
Если одновременно запущены бот на компьютере и бот на сервере с одним токеном — Telegram выдаёт Conflict, и ответы могут приходить от старой копии.

2. Выберите, где сейчас работает бот

Перезапуск на компьютере после новых настроек

  1. 1
    Остановите старую копию

    В окне, где бот запущен, нажмите Ctrl+C.

    Get-CimInstance Win32_Process -Filter "Name = 'python.exe'" |
  Where-Object { $_.CommandLine -like '*run.py*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
  2. 2
    Если меняли `.env`

    Сохраните файл. Новый запуск подхватит переменные только после перезапуска.

  3. 3
    Запустите бота снова 
    cd "ПУТЬ\К\ПРОЕКТУ"
.\.venv\Scripts\Activate.ps1
python run.py

    Дождитесь строки: Бот запущен (polling).

  4. 4
    Проверьте в Telegram

    Нажмите /start и пройдите сценарий заново. Кнопка «Старт» сама код не обновляет — она только начинает диалог.

Обновление и перезапуск на сервере

  1. 1
    Сначала отправьте код в GitHub 
    git add .
git commit -m "Описание изменений"
git push

    Это только обновляет репозиторий. Сервер ещё не знает про изменения.

  2. 2
    Остановите локального бота

    На компьютере не должно работать python run.py с тем же токеном.

  3. 3
    Зайдите на сервер 
    ssh root@ВАШ_IP
  4. 4
    Скачайте новый код и пересоберите контейнер 
    cd /opt/tg-bot-podarok
git pull
docker compose up -d --build
docker compose ps
docker compose logs -f --tail 50 bot

    Ищите в логах: Бот запущен (polling).

  5. 5
    Если меняли секреты

    Файл .env на сервере правится отдельно. Он не приезжает из GitHub.

    nano /opt/tg-bot-podarok/.env
docker compose up -d --build
Быстрые команды на сервере: остановить — docker stop tg-bot-podarok, запустить — docker start tg-bot-podarok, полностью выключить compose — docker compose down.

Почему нельзя держать две копии сразу

У бота один токен. Telegram разрешает только одному процессу забирать сообщения. Если запущены и локальная копия, и серверная, появляется ошибка Conflict, а пользователи могут получать ответы от старой версии.

Правило: одна рабочая копия = один источник правды. Для учебы — компьютер. Для постоянной работы — сервер.

3. Когда что делать

Сохраните `.env` и полностью перезапустите бота. Без перезапуска старые переменные останутся в памяти процесса.

6. Частые вопросы

Почему после push на сервере старые открытки?

Потому что сервер не получил новый код. Нужны `git pull` и `docker compose up -d --build`. Пока этого нет, Docker крутит старый образ.

Почему `/start` не помогает?

`/start` сбрасывает диалог пользователя, но не перезагружает программу бота. Новый код появляется только после остановки и нового запуска процесса/контейнера.

Что делать при ошибке Conflict?

Где-то ещё запущена вторая копия с тем же токеном. Остановите локальный `run.py` или контейнер на сервере: docker stop tg-bot-podarok.

Лимит открыток снова стал 0 после перезапуска?

В новой версии счётчик сохраняется в data/card_limits.json. На сервере эта папка должна быть смонтирована volume в docker-compose, иначе после пересоздания контейнера файл пропадёт.

Можно ли пушить `.env`?

Нет. Токены и ключи остаются только в локальном/серверном `.env`. В GitHub уходит код без секретов.
